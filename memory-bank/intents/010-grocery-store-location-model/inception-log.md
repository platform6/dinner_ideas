# Inception Log: grocery-store-location-model

## Overview

**Intent**: Rework the grocery-store-config data model from broad `category → row` mapping to
individual `Item (ingredient) → Location`, where a Location unifies `section` and `aisle`
stops in one ordered walking path, plus a similarity-suggestion assist for placing new
ingredients ("same place as pinto beans?"). Reworks the store-config page and the
shopping-list group-order sort. From `storeconfig.md` (Functionality Prompt half; the Design
Prompt is a separate design intent).
**Type**: brown-field (data-model remodel + migration + page rework; supersedes `001` u004)
**Created**: 2026-09-01

## Provenance

Generated by the Inception Agent from `storeconfig.md` (repo root) — a shared-context brief
with a Design Prompt and a Functionality Prompt, both of which name explicit open questions
"for the requester (Chandler)" and forbid silent assumptions. Cross-checked against the live
source: `grocery_store_rows` / `category_row_assignments` are **already household-scoped**
(`household_id` + `(household_id, position)` unique from `20260828231000`; direct RLS from
`20260828232000`); `reorder_grocery_store_row` RPC exists; `src/features/store-config/`
(`api.ts` / `hooks.ts` / `types.ts` / `StoreConfigPage.tsx`); ingredients are per-dinner
free-text `dinner_ingredients` rows (`name` + `category`) with **no** canonical Item table;
the `category → row` shopping-list sort is `001` unit `004`.
